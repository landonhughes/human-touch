# Web Design

## Goal

Design websites that feel like real shipped products, brands, publications, or services rather than generic AI landing-page concepts.

Human Touch should compose with specialized frontend, web-design, branding, UX,
copywriting, accessibility, SEO, and product skills.

## Start from the page's job

Before styling, determine:

- who the visitor is
- why they arrived
- what they need to understand
- what they should do next
- what belongs above the fold
- what objections need answering
- what evidence builds trust
- what content belongs later
- what information can be removed

The visual hierarchy should follow the information hierarchy.

## Common AI website tells

Watch for unmotivated:

- giant vague hero statements
- glowing gradient blobs
- decorative 3D objects
- fake dashboard screenshots
- excessive floating cards
- every section inside a rounded container
- every section using identical two-column layouts
- arbitrary glass panels
- fake analytics
- meaningless logo clouds
- generic testimonial cards
- fake metric counters
- decorative grids everywhere
- excessive pill-shaped labels
- giant typography with too little information
- identical spacing between every section
- gradients used simply because the product is "tech"
- four-column feature-card grids with interchangeable copy
- excessive centered text
- stock-like generated people without contextual reason

None of these are prohibited. They become a problem when they appear because they are defaults rather than deliberate choices.

## Section rhythm

A real page should have intentional pacing.

Possible section roles include:

- orientation
- problem
- product demonstration
- explanation
- proof
- comparison
- detail
- objection handling
- social proof
- pricing
- conversion

Do not make every section equally loud.

Alternate deliberately between:

- dense and quiet
- visual and textual
- explanatory and demonstrative
- proof and persuasion

Do not add sections merely to make the page longer.

## Layout variation

Avoid constructing the entire website from interchangeable cards.

Use the content to choose the layout.

Possible structures include:

- editorial text blocks
- full-width demonstrations
- comparison tables
- annotated screenshots
- timelines
- split layouts
- lists
- diagrams
- interactive demonstrations
- simple unboxed text

Containers should communicate grouping, not act as mandatory decoration.

## Real content

Use realistic:

- headlines
- navigation
- button labels
- product screenshots
- pricing
- FAQs
- testimonials
- examples
- states
- data

Placeholder content can make even excellent visual design feel synthetic.

## Responsive design

Consider at least:

- mobile hierarchy
- line length
- text wrapping
- navigation collapse
- touch targets
- content order
- horizontal overflow
- image cropping
- responsive tables
- sticky elements
- reduced motion
- viewport height
- safe areas where relevant

Do not treat mobile as a scaled-down desktop screenshot.

## Interactions

Motion and interaction should support:

- navigation
- disclosure
- feedback
- orientation
- emphasis
- demonstration

Avoid adding scroll effects, cursor effects, parallax, or hover animation to every element simply to make the site feel sophisticated.

## Marketing-site realism

A polished website should still feel buildable.

Check:

- whether the hero works at common viewport sizes
- whether real copy fits the layout
- whether cards tolerate variable text lengths
- whether buttons have realistic labels
- whether screenshots correspond to an actual product
- whether navigation is understandable
- whether the page has a credible conversion path

## Web review question

Ask:

> If I removed the gradients, mockups, and animations, would the page still have a strong information architecture and visual hierarchy?

If not, the page may be relying on decoration instead of design.
